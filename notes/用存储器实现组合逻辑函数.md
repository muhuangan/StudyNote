# 用存储器实现组合逻辑函数

## 核心结论

把 ROM 的**地址线当作输入变量, 数据线当作输出函数值**, 真值表逐行写入存储单元, ROM 就成为一台"组合逻辑函数发生器". 它不需要任何化简, 特别适合**多输出, 变量多, 逻辑复杂**的函数.

## 一、为什么 ROM 能实现逻辑函数

ROM 内部是"固定的与阵列 + 可编程的或阵列":

- **与阵列**(地址译码器) 固定产生输入的全部 $2^n$ 个最小项.
- **或阵列**(存储矩阵) 决定哪些最小项被输出到某一位.

因此对于 $n$ 输入,$m$ 输出的任意组合逻辑函数, 只要把每一个输入组合对应的 $m$ 位输出值写入相应的存储单元即可.

**关键认识**: ROM 存的是**真值表**, 而真值表是逻辑函数的完备描述, 因此 ROM 可以实现任意组合逻辑函数.

## 二、实现步骤

1. 确定输入变量个数 $n$ 与输出函数个数 $m$.
2. 选一片容量不小于 $2^n \times m$ 的 ROM(或 EPROM, EEPROM, Flash).
3. 把 $n$ 个输入变量接到 ROM 的地址端 $A_0$ 至 $A_{n - 1}$.
4. 列出真值表(或直接由函数式求各最小项的输出值).
5. 把真值表的每一行的 $m$ 位输出值写入对应地址的存储单元.
6. $m$ 个输出端即为函数输出.

## 三、示例

**题目**: 用 ROM 实现两个 3 变量函数

$$F_1(A,B,C) = \sum m(0, 1, 3, 5)$$

$$F_2(A,B,C) = \sum m(2, 3, 6, 7)$$

**实现**: 选一片 $8 \times 2$ 位(或更大的) ROM, 把 $A$,$B$,$C$ 接到 $A_2$,$A_1$,$A_0$.

| 地址 | $F_1$ | $F_2$ | 存储内容($F_1 F_2$) |
| ---- | ----- | ----- | ------------------- |
| 000  | 1     | 0     | 10                  |
| 001  | 1     | 0     | 10                  |
| 010  | 0     | 1     | 01                  |
| 011  | 1     | 1     | 11                  |
| 100  | 0     | 0     | 00                  |
| 101  | 1     | 0     | 10                  |
| 110  | 0     | 1     | 01                  |
| 111  | 0     | 1     | 01                  |

把上表最后一列依次写入地址 0 至 7, 两个数据输出端即为 $F_1$,$F_2$.

**扩展**: 若同时需要 8 个输出函数, 只需把数据线扩到 8 位, 其余完全不变. 这正是 ROM 方案在多输出场合的巨大优势.

## 四、ROM 方案与门电路方案的对比

| 对比项       | ROM                          | 门电路 / MSI         |
| ------------ | ---------------------------- | -------------------- |
| 是否需要化简 | **不需要**                   | 需要                 |
| 设计难度     | 低(填表即可)                 | 高                   |
| 变量数适应性 | 强($2^n$ 随 $n$ 指数增长)    | 弱(变量多时化简困难) |
| 多输出能力   | 强(多加数据位即可)           | 每组输出需单独设计   |
| 资源利用率   | 低(只用了一小部分存储单元)   | 高                   |
| 速度         | 较慢(有地址译码延迟)         | 快                   |
| 可修改性     | 强(重新烧录即可, 尤其 Flash) | 弱(需改电路)         |
| 成本         | 复杂函数时低                 | 简单函数时低         |

## 五、用 RAM 实现组合逻辑函数

RAM 也能实现组合逻辑函数, 但**必须先写入**内容, 且断电后丢失, 因此实际应用很少. 它只在需要"动态改变逻辑功能"(可重构逻辑) 的场合有意义.

**对比结论**: 实现固定逻辑函数用 **ROM**, 需要动态改变逻辑内容时才考虑 RAM. 现代 FPGA 中的查找表(LUT) 本质上就是一个小型 SRAM, 配置时把真值表写入, 工作时按地址查表—这可以看作"用 RAM 实现组合逻辑函数"的现代形态.

## 六、ROM 与 PLD 的关系

| 器件 | 与阵列       | 或阵列             | 特点                   |
| ---- | ------------ | ------------------ | ---------------------- |
| ROM  | 固定(全译码) | 可编程             | 资源浪费大, 但最简单   |
| PLA  | 可编程       | 可编程             | 利用率最高, 但编程复杂 |
| PAL  | 可编程       | 固定               | 折中, 曾广泛使用       |
| GAL  | 可编程       | 固定(带输出宏单元) | 可重复编程             |

可见 ROM 是"与阵列固定"的极端情形, 这也是它资源利用率低的原因: 即使函数只用到极少数最小项,$2^n$ 条字线也全部存在.

## 七、适用场景判断

| 场景                           | 推荐                      |
| ------------------------------ | ------------------------- |
| 单输出, 变量少于 5             | 门电路或数据选择器        |
| 多输出, 变量较多, 逻辑复杂     | **ROM**                   |
| 需要经常修改逻辑               | ROM / Flash / CPLD / FPGA |
| 对速度要求极高                 | 门电路或专用逻辑          |
| 函数本质是查表(如字库, 编码表) | ROM                       |

## 八、容量估算

实现 $n$ 输入,$m$ 输出的组合逻辑, 所需 ROM 容量为

$$容量 = 2^n \times m\ \text{位}$$

变量每增加 1 个, 容量翻倍. 因此变量超过 12 个($2^{12} = 4096$) 时 ROM 方案的成本会急剧上升, 此时应改用 PLD/FPGA 或对函数做分解.

## 易错点

- 地址线与变量的对应关系必须固定(最高位变量接最高位地址), 接反会导致功能完全错误.
- 认为"ROM 只能存数据": 从结构上看, ROM 就是一个可编程的与或阵列, 天然可以实现逻辑函数.
- 忽略地址译码延迟: ROM 方案的响应速度通常比门电路方案慢.
