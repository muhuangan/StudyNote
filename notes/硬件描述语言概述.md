# 硬件描述语言概述

## 核心结论

硬件描述语言(HDL) 用文本描述**电路的结构与行为**, 经综合工具映射为实际的门电路与触发器. 它与软件语言的根本区别在于: **HDL 的语句是并行的, 描述的是同时存在的硬件, 而不是顺序执行的指令流**.

## 一、为什么需要 HDL

1. **规模**: 现代数字电路可达数千万门, 画原理图已经不可行.
2. **抽象**: HDL 可以在行为级描述功能, 把实现细节交给综合工具.
3. **可移植**: 同一份代码可以在不同工艺, 不同器件上实现.
4. **可验证**: 仿真工具可以在制造前验证功能与时序.
5. **可复用**: IP 核以 HDL 形式交付, 易于复用.

## 二、Verilog 与 VHDL

| 对比项   | Verilog HDL                                             | VHDL                         |
| -------- | ------------------------------------------------------- | ---------------------------- |
| 起源     | Gateway Design Automation(1984), 后被 Cadence 收购      | 美国国防部(VHSIC 项目, 1987) |
| 语法风格 | 类似 C 语言, 简洁                                       | 类似 Ada, 严谨冗长           |
| 类型系统 | 弱类型, 宽松                                            | 强类型, 严格                 |
| 学习曲线 | 平缓                                                    | 陡峭                         |
| 流行度   | 工业界(尤其北美, 中国) 最广泛                           | 欧洲, 军工, 航天较多         |
| 标准     | IEEE 1364(1995 / 2001), 后并入 SystemVerilog(IEEE 1800) | IEEE 1076                    |

**建议**: 初学从 Verilog 入手, 语法负担小; 需要严谨的类型检查与文档化时考虑 VHDL. 现代工业界越来越多地使用 **SystemVerilog**(Verilog 的超集, 增强了验证能力).

## 三、抽象层次

| 层次                     | 描述内容                       | 可综合性                 |
| ------------------------ | ------------------------------ | ------------------------ |
| 系统级 / 行为级          | 算法, 数据流, 不考虑硬件细节   | 部分可综合               |
| **RTL 级(寄存器传输级)** | 寄存器之间的数据传输与组合逻辑 | **完全可综合, 工程主力** |
| 门级                     | 逻辑门与连线                   | 可综合                   |
| 开关级(晶体管级)         | MOS 管                         | 一般不可综合, 仅用于仿真 |

**RTL 级的核心思想**: 把电路看成"寄存器堆 + 组合逻辑块", 用"在时钟沿把组合逻辑的结果装入寄存器"来描述一切时序行为.

## 四、模块的基本结构

```verilog
module 模块名 #(
    parameter 参数名 = 默认值
)(
    input   wire [位宽] 端口1,
    output  reg  [位宽] 端口2,
    inout   wire [位宽] 端口3
);

// 内部信号声明
wire [位宽] 内部连线;
reg  [位宽] 寄存器变量;

// 功能描述
assign 连续赋值语句;

always @(敏感表) begin
    过程赋值语句;
end

// 模块实例化
子模块名 实例名 (.端口1(信号1), .端口2(信号2));

endmodule
```

**要点**:

1. `module` 与 `endmodule` 成对出现, 构成设计的基本单元.
2. 端口列表定义了模块的对外接口.
3. 模块可以**实例化**其他模块, 形成层次化设计.
4. 模块名通常与文件名一致(工具约定).

## 五、端口的三种方向

| 方向 | 关键字   | 说明                       |
| ---- | -------- | -------------------------- |
| 输入 | `input`  | 模块内部只能读取, 不能驱动 |
| 输出 | `output` | 模块内部驱动, 外部读取     |
| 双向 | `inout`  | 双向端口, 需配合三态控制   |

**端口的数据类型**:

- `input` 与 `inout` 必须是 `wire` 型.
- `output` 可以是 `wire`(由 `assign` 驱动) 或 `reg`(由 `always` 块驱动).

## 六、Verilog 与软件语言的根本区别

| 对比项      | C 语言         | Verilog                                       |
| ----------- | -------------- | --------------------------------------------- |
| 执行方式    | 顺序执行语句   | **并行**: 所有 `always`,`assign` 同时有效     |
| 变量含义    | 内存中的值     | **硬件连线(wire) 或寄存器(reg)**              |
| 赋值语义    | 立即改变变量值 | 阻塞赋值立即生效,**非阻塞赋值在块结束时生效** |
| 时间概念    | 无             | 有延迟, 有事件调度                            |
| `if`/`case` | 控制流         | **综合成多路选择器**                          |
| 循环 `for`  | 控制流         | 综合为**展开的重复硬件**(或不可综合)          |

**最重要的心智转变**: 写 Verilog 时脑子里想的应该是"这段代码会变成什么样的电路", 而不是"这段代码会按什么顺序执行".

## 七、可综合子集

**定义**: 可以被综合工具转换成实际硬件的那部分 Verilog 语法.

**可综合**:

- `module`,`input`,`output`,`wire`,`reg`,`parameter`
- `assign` 连续赋值
- `always @(posedge clk)`,`always @(*)`
- `if / else`,`case`,`? :`
- 算术与逻辑运算符
- 模块实例化

**不可综合**(只能用于仿真):

- `initial` 块(给 FPGA 寄存器赋初值除外)
- 延迟控制 `#10`
- `$display`,`$monitor`,`$finish` 等系统任务
- `fork / join`
- 部分循环(无确定边界的 `while`)

**实践建议**: 写 RTL 时严格使用可综合子集; 测试平台(testbench) 才可以使用全部语法.

## 八、开发流程中的位置

$$HDL 代码 \xrightarrow{综合} 门级网表 \xrightarrow{布局布线} 器件配置数据$$

- **功能仿真**(前仿真): 验证逻辑功能, 不考虑延迟.
- **综合**: 把 RTL 映射为器件的逻辑资源.
- **时序仿真**(后仿真): 加入实际延迟后验证, 检查建立/保持时间.

## 九、学习路线建议

1. 掌握模块结构与端口定义.
2. 掌握 `wire` 与 `reg` 的区别.
3. 掌握 `assign`(组合逻辑) 与 `always @(posedge clk)`(时序逻辑) 两种写法.
4. 理解阻塞与非阻塞赋值的区别(最关键).
5. 练习描述常用电路: 多路选择器, 译码器, 计数器, 移位寄存器, 状态机.
6. 学会写 testbench 并仿真验证.

## 易错点

- 把 Verilog 当 C 语言顺序执行来写: 所有 `always` 块是**并行**的, 块内才是顺序的.
- 认为所有 Verilog 语法都能变成电路: 只有**可综合子集**能综合, 仿真专用的语法在硬件上不存在.
