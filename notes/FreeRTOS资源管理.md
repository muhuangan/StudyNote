# 资源管理

1. 问题: 多个任务或中断共享变量与外设时, 读改写过程可能被抢占或打断, 造成数据不一致; 管理手段就是让临界代码段不被打断
2. 保护手段概览
    1. 临界区: taskENTER_CRITICAL 关屏蔽阈值以下的中断, 用于极短的几条语句
    2. 挂起调度器: vTaskSuspendAll 阻止任务切换但仍响应中断, 只能保护任务间共享的数据
    3. 信号量: 以 take 与 give 计数, 用于事件同步
    4. 互斥锁: 保护可能耗时的资源访问
3. 信号量: 基于队列实现, 见 [队列管理](./FreeRTOS队列管理.md)
    1. 二值: 计数只有 0 与 1, 中断里 xSemaphoreGiveFromISR 通知, 任务里 xSemaphoreTake 阻塞等待, 常用作中断到任务的同步
    2. 计数: 上限为 N 的资源池, take 减 1, give 加 1, 限制同时使用某资源的任务数量
4. 互斥锁
    1. 用法: xSemaphoreCreateMutex 创建, take 到锁才能访问资源, 用完 give 归还, 必须由持有任务归还
    2. 优先级继承: 高优先级任务等待互斥锁期间, 持锁任务的优先级临时提升到等待者水平, 归还后恢复
    3. 优先级反转: 没有继承机制时, 低优先级任务持锁又被中优先级任务抢占, 高优先级任务被间接拖住, 火星探路者号曾因这一问题反复复位
    4. 死锁: 两个任务互相持有对方需要的锁且互不释放, 预防办法是约定统一的加锁顺序
5. 选择原则
    1. 保护几条语句: 临界区
    2. 只在任务间共享且访问极快: 挂起调度器
    3. 中断通知任务: 二值信号量, 或 [任务管理](./FreeRTOS任务管理.md) 中的任务通知
    4. 资源访问可能耗时或阻塞: 互斥锁
6. 注意: 持锁或处于临界区期间不得调用会阻塞的函数, 否则其他任务被无限拖延
