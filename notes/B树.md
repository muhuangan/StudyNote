# B树

很多查找不是在内存中完成的而是在磁盘中完成的, 但磁盘的读写代价很高, 这时二叉排序树由于高度容易过高, 显得有些力不从心, 为了解决这个问题, 人们提出了一种多路平衡查找树, 即B树(Balanced Tree或Bayer Tree)

**B树**: 又名B-树, 简单来说, B树是多路版本的平衡查找树, 或是叫平衡多叉树, 允许每个节点有多个关键字和多个孩子, 这种结构可以有效压缩树的高度

**B树的性质**:  
一个m阶的B树的性质如下

1. 每个节点最多有m个孩子
2. 每个非根非叶子节点至少有 $\left\lceil m/2 \right\rceil$ 个孩子
3. 每个非叶子节点有k个孩子就有k-1个关键字
4. 关键字按照中序遍历是有序的
5. 关键字在节点中是排好序的, 关键字在孩子之间穿插, 每个孩子对应一个区间
6. B树的所有叶子节点都在同一层

以三阶B树为例看一下B树的插入, 查找和删除

- **插入**
    1.  查找插入位置(从根开始) 找到要插入的关键字应该落在哪个叶子节点
    2.  将关键字插入该叶子节点的合适位置, 如果该节点未满, 直接插入, 结束. 如果插入后超出最大关键字数, 触发分裂
    3.  分裂: 关键字"上移", 节点一分为二, 中间的关键字上升到父节点, 分裂产生的两个子节点平分原数据, 父节点接收中间关键字及新子节点指针
    4.  父节点若满, 继续向上传递(递归分裂), 最终可能导致根节点分裂->树高增加

- **删除**
    - 查找目标关键字的位置(从根开始), 从根节点开始查找目标关键字
        - 若找到关键字:
            - 如果该节点是叶子节点, 可以直接删除
            - 如果该节点是非叶子节点, 需转化为在叶子节点中的删除(转换为删除其前驱或后继关键字)
                1. 从该节点的左子树中找到最大值(前驱), 或从右子树中找到最小值(后继)
                2. 用该值替换关键字, 然后在叶子节点中递归删除前驱/后继值. 目的: 让真正的删除操作都发生在**叶子节点**, 便于处理
                3. 删除前判断目标子节点是否安全, 若不安全, 删除后要做"填充"或"合并"
                    - 填充:  
                      假设要进入第i个子节点C\[i\] 删除:
                    - 情况一: 左兄弟C\[i-1\] 存在, 且关键字树 > $\left\lceil m/2 \right\rceil - 1$ -> 借用, 从父节点拿一个关键字下调至C\[i\]; 左兄弟把自己的最大关键字上调至父节点; 若有子树, 调整指针结构
                    - 情况二: 右兄弟C\[i+1\] 存在, 若关键字数 > $\left\lceil m/2 \right\rceil - 1$ -> 借用, 从父节点拿一个关键字下调至C\[i\]; 右兄弟把自己的最小关键字上调至父节点; 若有子树, 调整指针结构
                    - 合并:  
                      两边兄弟都不足, 将当前子节点与一个兄弟节点合并成一个新节点; 父节点中对应的关键字也下调进入合并节点; 父节点关键字数量减少 -> 若也不足, 再继续向上传递
        - 若未找到关键字, 递归进入对应的子节点继续查找

- **查找**
  按中序遍历的方式遍历一棵树

1. 从根节点开始, 逐层向下查找  
   从当前结点中, 从左到右依次比较关键字:
    - 如果等于某个关键字, 查找成功 - 如果小于某个关键字, 就转入改关键字左边的子树 - 如果大于所有关键字, 就转入最右边的子树
2. 继续在子树中重复上述过程, 直到查找成功或遇到叶子节点. 若在叶子节点中也没有找到, 说明目标关键字不存在于该B树中; 若在中途命中关键字, 查找结束, 返回该位置
3. 整个过程本质上是"在结点内查找 + 递归进入子树" 交替进行, 直到命中或结束

**B树的好处**

- 减少磁盘读写次数: 由于节点内存储多个关键字, 树的高度被显著降低, 从而减少了磁盘访问
- 适用于大数据量场景: B树特别适用于数据库索引和文件系统等需要高效读写大量数据的应用
