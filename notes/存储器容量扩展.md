# 存储器容量扩展

## 核心结论

扩展分三种: **位扩展**(加宽字长),**字扩展**(增加字数),**字位同时扩展**. 判断方法很简单—先算清楚"缺的是位数还是字数", 然后按对应的连线规则连接: 位扩展**并联地址, 分开数据**, 字扩展**并联数据, 译码地址高位产生片选**.

## 一、扩展前的容量计算

单片容量:

$$容量 = 2^{n} \times m$$

其中 $n$ 为地址线数,$m$ 为数据线数.

**目标**: 把若干片 $2^n \times m$ 的芯片拼成 $2^N \times M$.

| 需求                          | 所需片数                      |
| ----------------------------- | ----------------------------- |
| 位扩展($N = n$,$M > m$)       | $M / m$ 片                    |
| 字扩展($N > n$,$M = m$)       | $2^{N - n}$ 片                |
| 字位同时扩展($N > n$,$M > m$) | $2^{N - n} \times (M / m)$ 片 |

## 二、位扩展(加长字长)

**适用**: 字数够, 但每字的位数不够. 例如用 2 片 $1\text{K} \times 4$ 构成 $1\text{K} \times 8$.

**连线规则**:

1. **地址线并联**: 所有芯片的地址输入端接同一组地址线.
2. **片选并联**: 所有芯片的 $\overline{CS}$ 接在一起(同时工作).
3. **读写控制并联**.
4. **数据线分开**: 各片的 $I / O$ 分别作为总数据线的不同位段.

**示例**: 2 片 $1\text{K} \times 4$ 组成 $1\text{K} \times 8$.

- 地址线 $A_0$ 至 $A_9$ 同时接两片.
- 片 1 的 $I / O_0$ 至 $I / O_3$ 作为 $D_0$ 至 $D_3$.
- 片 2 的 $I / O_0$ 至 $I / O_3$ 作为 $D_4$ 至 $D_7$.

## 三、字扩展(增加字数)

**适用**: 位数够, 但字数不够. 例如用 4 片 $1\text{K} \times 8$ 构成 $4\text{K} \times 8$.

**连线规则**:

1. **低位地址并联**:$A_0$ 至 $A_{n - 1}$ 同时接所有芯片的地址端(片内寻址).
2. **高位地址译码产生片选**: 多出来的高位地址 $A_n$ 至 $A_{N - 1}$ 经译码器产生 $2^{N - n}$ 个片选信号, 分别接各片的 $\overline{CS}$.
3. **数据线并联**: 所有芯片的同名数据端并联到总数据线.
4. **读写控制并联**.

**关键点**: 任意时刻只能有一片被选中(否则数据线冲突), 因此片选信号必须**互斥**.

**示例**: 4 片 $1\text{K} \times 8$(地址 $A_0$ 至 $A_9$) 组成 $4\text{K} \times 8$(地址 $A_0$ 至 $A_{11}$).

- $A_0$ 至 $A_9$ 并联接 4 片的地址端.
- $A_{10}$,$A_{11}$ 接一个 2 线 - 4 线译码器(如 74LS139), 4 个输出各接一片的 $\overline{CS}$.
- 4 片的 8 位数据端并联成系统数据总线.

**用译码器还是直接用高位地址**: 若只有 1 位高位地址, 可直接接(一片接原值, 一片接反相值); 2 位及以上必须用译码器, 否则无法保证互斥.

## 四、字位同时扩展

**做法**: **先位扩展成组, 再把组做字扩展**.

**步骤**:

1. 用 $M / m$ 片做位扩展, 得到若干个"字长已满足要求的组".
2. 把这些组按字扩展方式连接(高位地址译码产生各组的片选).

**示例**: 用 $1\text{K} \times 4$ 芯片构成 $4\text{K} \times 8$ 存储器.

- 每组需要 $8 / 4 = 2$ 片做位扩展.
- 需要 $4\text{K} / 1\text{K} = 4$ 组做字扩展.
- 总片数 $= 2 \times 4 = 8$ 片.

## 五、片选信号的两种产生方式

| 方式           | 做法                         | 特点                                     |
| -------------- | ---------------------------- | ---------------------------------------- |
| 线选法         | 直接用高位地址线作为片选     | 简单, 但地址空间不连续, 有重叠, 浪费地址 |
| 译码法(全译码) | 全部高位地址经译码器产生片选 | 地址连续, 无重叠, 资源利用率高,**推荐**  |

**全译码**的优点是每一块存储区对应唯一的一段地址, 不会出现"一个地址同时选中两片"的冲突.

## 六、与 CPU 连接时的要点

1. **地址分配**: 先规划好各存储区与 I/O 区的地址范围, 再设计译码逻辑.
2. **片选互斥**: 任何时刻只能有一片与 CPU 交换数据.
3. **总线驱动**: 若芯片数量多, CPU 的地址/数据总线需要加缓冲器(如 74LS244/245).
4. **时序匹配**: CPU 的读写时序必须满足存储器的地址建立时间, 读写脉宽等要求; 若存储器较慢, 需插入**等待周期**.
5. **三态输出**: 未选中的芯片必须处于高阻态.

## 七、常见故障排查

| 现象                   | 原因                             |
| ---------------------- | -------------------------------- |
| 数据总线冲突, 读写错误 | 片选信号未互斥, 两片同时被选中   |
| 部分地址范围读写异常   | 地址线接错(高低位接反或漏接一根) |
| 高位地址不起作用       | 高位地址未参与译码(误用线选法)   |
| 读写数据错乱           | 读写控制信号时序不满足           |

## 易错点

- 位扩展时把数据线也并联了: 位扩展的数据线必须**分开**接到不同的位段, 并联会导致数据冲突.
- 字扩展时忘记把低位地址并联: 片内寻址依赖低位地址, 不接则无法访问片内单元.
- 用线选法时未意识到地址重叠: 线选法下存在"一个物理单元对应多个逻辑地址"的问题.
